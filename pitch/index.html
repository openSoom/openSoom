What runs in the background?

Facility operations app
Sends allowed equipment commands and checks recovery. The facility MN-CSE stores the original observations and enforces access by application identity.
Edge maintenance app
Maintains the work order and selects a first inspection from verified evidence. It runs as its own workload in the Option C deployment.
MEC service bridge
Connects an approved external sensor provider through MEC 033 and obtains a shaft reading through MEC 046. A site with its own independent sensor can read it locally.

Deployment choices

Where does the shaft reading come from?

The facility keeps control of its equipment. A separately managed sensor can join through a bridge when the site needs it.

Site operations

Reads zone observations, sends the damper command and checks later airflow on the facility’s MN-CSE. The central IN-CSE can reach shared site resources over Mcc.

Maintenance

Reads the outcome, opens one work order and asks for the shaft position. Only this app changes the inspection priority. For Option C, the Sandbox deployed this worker alongside the MN-CSE on two successive logical edges of one VM. Inspect north and south placements ↗

The bridge reads a separate sensor AE’s content instance. The maintenance app receives a measurement with its sensor ID, unit and observation time.

    ADAPT ONCE

    Different formats.
    Common meaning.

    One vendor reports dust in mg/m³ and flow in litres per second. Another uses µg/m³ and m³/h. Adapters preserve meaning and timestamps before the same diagnostic code sees the data.

    vendor B: 0.012 mg/m³
    canonical: 12 µg/m³
    SDT PM2.5: 12 µg/m³

    The original observation retains precision. The standard PM2.5 projection is an integer. CO₂ ppm is not assigned to the incompatible SDT mass-concentration field.

    Why oneM2M?

    Shared discovery, subscriptions, fan-out, access control and remote resources reduce repeated integration work. Facility rules stay in the openSoom core. A single-vendor installation may need a simpler API.

    What these demonstrations establish

    The film opens on a local ACME particle alert, then follows a separate cloud maintenance incident with a virtual shaft sensor and actual MEC 046 retrieval. Separate engineering runs verified TLS, Codex and hosted-model tools, a serving-CSE handover and a cloud maintenance deployment on two logical edges of one VM.

    Further validation: physical adapters, human first-use usability, a separate Codex desktop UI flow and production network identity.

    Outside release claims: multi-physical-host placement, federated learning, network geolocation and clinical or certified ventilation outcomes.

    Model prose, a successful command write and a promotional visualization are never used alone to establish recovery.
