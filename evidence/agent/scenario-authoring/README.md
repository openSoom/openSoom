# Facility manager scenario acceptance

All equipment and readings in these tests were simulated. ACME, the openSoom service, the MCP plugin, Codex and the named hosted model ran as software. The rehearsal used a dedicated instance of learning-b. The dashboard on the final demo ports was left running.

| Capture | Observed result |
| --- | --- |
| [Saved version across restart](restart-acceptance.json) | A new trial targeted lounge, the third zone. The API process was stopped and restarted with the same SQLite database and CSE. The service replayed the same definition, independently retrieved its observation CIN, refused the stale command, and observed zero increments in the CSE command container. Neighboring command, observation and ACK containers retained their state tags. An intentional fresh contrast produced one command and an ACK. Changing only the stale trial's expectation produced a failed assertion. |
| [Standalone hosted model](standalone-verified.json) | The model called save, run and read through stdio MCP. The service correlated the version and execution with the original CIN and confirmed the refusal. The operational outcome is a refusal under the learning-space simulation profile. |
| [Initial standalone attempt](standalone-live.json) | The model repeatedly saved the same version and hit its step limit. The authoring runner now removes successful operations from the available actions for that request. |
| [Codex host read](codex-host-read.json) | A clean Codex installation loaded the plugin and independently retrieved the standalone execution and its exact original CSE observation. The harness selected this read-only lookup. It made zero provider calls. |
| [Codex preflight](codex-preflight.json) and [model-selected native tool](codex-live.json) | The installed plugin exposed its immediate-test operation. The model requested that tool but supplied the scenario ID in the zone field. The isolated Codex client was configured with read-only filesystem access and approval policy `never`. The host required an approval and rejected the call before sending it to openSoom. This run created no definition or command through Codex. |

The [second native Codex execution](codex-verified-retry.json) generated the correct new scenario ID, the distinct zone `lounge`, a 345 m³/h reading aged 93 seconds, and an 83% requested damper setting. The normal per-call approval matched this exact preauthorized virtual test. It created the saved definition, ran it, and read the original observation CIN with zero commands. The original rehearsal checker expected optional per-call receipt fields missing in this earlier operations process. Its raw flag records that reporting mismatch. The [post-restart audit](codex-authored-accepted.json) verified the three persisted tool names, every original argument, execution/version relation, stored definition hash, original CIN and a separate replay with a new CIN. No further completions were needed for this audit. The original Codex compound tool selection and the three underlying service operations are recorded separately.

After the final retry the shared persistent budget retained 17 inference requests and 2,314 tokens. The test reserved the remaining allowance in advance, measured input with the provider's token-counting API, and charged the counted input conservatively in addition to actual inference usage.

For deterministic reproduction, start an isolated CSE and API with the virtual learning-b facility. Run `scripts/scenario_authoring_acceptance.py prepare` with the service URL, CSE URL, runtime directory and output file. Restart only that API process and run the script with `replay` and the same arguments. To look up a known execution from the native plugin, use `scripts/codex_scenario_rehearsal.py --read-execution EXECUTION_ID --service URL --runtime DIRECTORY --output FILE`.
