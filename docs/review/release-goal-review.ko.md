## 메인 에이전트의 반영 결정

- **A · D**의 요청을 R1·R2에 채택했다. 기존 정비 역할은 일부 장치 명령 쓰기 권한이 있어 새 정비 앱에 그대로 부여할 수 없다. 전용 신원의 범위, CSE에서 놓친 사건 재조회, 작업 쓰기 직후 재시작, 첫 구역 이외의 시나리오와 양쪽 에이전트 실행을 검증한다. 시연 데이터셋을 격리해 기존 활성 사건을 보존한다.
- **E**의 지적에 따라 R3에 oneM2M 측 서비스 요청과 CSE 응답 재조회를 넣었다. MEC 046 조회를 정비 앱이 직접 하고 결과만 CSE에 쓰는 흐름은 16번의 ‘through oneM2M’ 입증을 보장하지 않는다. 플랫폼 배포, 서비스 한 개의 사용, Expert 수준의 다중 서비스·호스트 오케스트레이션을 단계별로 기록한다.
- **B · C**의 요청을 R4·R5에 채택했다. 현행 코드에는 완성된 영문 슬라이드 파일이 추적되지 않고 기존 영상은 1080p다. 새 데모와 영어 PPTX·PDF를 실제로 열어 리허설하고 최종 커밋의 클린 설치와 공개 파일을 확인한다. 실제 게시·공개 논의·인터뷰는 발생 시점에만 기록한다.
- **F**의 조건부 제안을 보존했다. 원시 현장 데이터를 공유할 수 없는 다기관 학습 또는 이동 단말의 구역 전환이 실제 운영 결정에 필요한 경우 범위를 연다. 고정 팬의 상태 판정에는 현재 프로필과 측정값으로 충분하다. 제출본에서 14·15를 Expert 또는 공식 N/A로 표시하지 않는다.

검토 결과는 [발견 및 조치 기록](review-ledger.json)에 남겼다. 새 실행의 판정은 담당팀이 같은 릴리스 후보에서 독립 재확인한다.
