# openSoom Goal 모드 시작 프롬프트

이 파일은 다음 구현 실행을 위한 프롬프트입니다. 문서 준비만으로 Goal이 시작되지는 않습니다. 이 저장소를 작업 공간으로 열고 아래 블록을 전달하세요. 이미 진행 중이라면 처음부터 다시 만들지 않고 미완료 기준부터 재개하도록 구성했습니다.

```text
Goal 모드로 openSoom 구현 목표를 등록하고 0단계부터 실행해주세요. 기존 활성 목표가 같은 작업이면 이어가고, 다른 목표라면 임의로 덮어쓰지 마세요. 토큰 예산은 제가 별도로 지정하지 않았으므로 임의의 예산을 설정하지 마세요.

목표: openSoom/openSoom 저장소에 재현 가능한 oneM2M 기반 시설 공기 관리 제품과 해커톤 제출 준비 패키지를 완성합니다. 단계 0~6의 필수 완료 기준을 실제 실행 증거와 독립 검토로 충족하고, 검토된 결과를 github-personal 명의로 저장소에 반영합니다. 학교 급식실은 예시이며, 식품 생산 및 다른 환기 필요 시설에 같은 코어를 재사용할 수 있어야 합니다.

먼저 AGENTS.md, docs/product-contract.json, docs/implementation-plan.md, docs/execution-state.json, docs/hackathon/rubric-baseline.json, docs/review/review-charter.json, docs/review/review-ledger.json과 현재 코드를 읽으세요. 계획 파일 자체가 0단계 완료 증거는 아닙니다. 이미 완료한 작업은 확인 후 이어갑니다.

반드시 구현하고 증명할 결과:
- 가상 센서 → 실제 oneM2M CSE → 진단/사건 → 권한 내 조치 → 장비 ACK → 이후 관측값을 통한 결과 검증. 누락·오래된 값·응답 없음·회복 실패를 성공으로 처리하지 않습니다.
- 공통 코어와 MCP 코드를 바꾸지 않는 두 시설 프로필 및 두 제조사 어댑터, 실제 발견·구독·그룹 기능, 역할별 ACP와 보안 통신, FCNT·discovery·어댑터 의미/단위 검증. 고급 SDT/semantic 모델은 별도 조건부 기준으로 우선 검토하고 채택 시 실제 검증합니다.
- 비개발자가 사용할 Codex 플러그인의 설치·설정·진단·재시작 경험과, 같은 도구 경로를 쓰는 독립 실제 LLM API 실행기. 모델이 도구를 호출하고 CSE 결과까지 검증해야 합니다.
- 서비스에 저장되는 실행/사건 상태, 권한·시설·프로필·데이터 유효성 검사, 제한된 재시도와 실행량, 비밀값을 제외한 추적 기록.
- 단일 시설의 간단한 시작 경로, 복수 시설 CSE와 중앙 운영의 실제 연동, 실행 상태를 보여주는 대시보드와 퀄리티 높은 시각화·영상.
- 재현 가능한 공개 저장소, 영어 Hackster 초안과 영상 파일, 발표 자료·Q&A, 실행 증거와 제한사항이 일치하는 제출 준비 패키지.

진행 중 저는 답변하거나 승인할 수 없습니다. 일상적인 선택, 단계 전환, 이미 허용한 저장소 반영을 재확인하지 말고 자율적으로 진행하세요. 언어·라이브러리·세부 구조·작업 분할·구현 순서는 필요에 따라 바꾸되, 변경 이유와 영향을 받는 완료 기준을 기록하고 관련 팀의 검토를 받으세요. 필수 결과를 조용히 삭제하거나 실패한 기준을 완화해서 완료 처리하지 마세요.

4개 Rubric 담당팀을 유지하세요. 모델은 GPT-6.1 Sol(gpt-6.1-sol), reasoning은 max입니다. 기존 역할이 없으면 명시적인 작업 맥락과 같은 증거 묶음을 제공해 재생성하세요. 새 에이전트에 모델/추론 설정을 지정할 때 fork_turns는 none을 사용합니다.
- 팀 1: 기준 1, 2, 3, 11 / rubric_reviewer
- 팀 2: 기준 4, 5, 6, 7 / oss_experience_review
- 팀 3: 기준 8, 9, 10, 17 / architecture_reasonableness
- 팀 4: 기준 12, 13, 14, 15, 16 / edge_standards_review
동시 실행은 메인 포함 4개 제한을 지키고 필요하면 나누어 실행하세요. 주요 변경은 담당팀, 0단계 설계 확정·첫 CSE 전체 동작·Codex/LLM 수용 검증·출시 후보·최종 패키지는 4팀 모두 검토합니다. 의견은 수용/대안/보류와 이유를 기록하고, 메인이 구현 에이전트를 자유롭게 활용해 보완한 다음 독립 검증을 받습니다. 구현자의 자체 확인만으로 의견을 닫지 마세요.

막힘 대응:
- MEC·외부 API·설치 권한의 가용성은 초기에 제한된 시간으로 확인하고, 막힌 항목은 기록한 뒤 독립적으로 가능한 코어·어댑터·UI·테스트·문서를 계속합니다.
- 이미 설정된 사용 가능한 모델 API를 제한된 실행량으로 사용하세요. 0단계에서 호출별 제한과 별도로 전체 테스트 묶음의 유한한 요청·토큰 한도를 정하고, 모든 작업자·재시도·재시작의 사용량과 호출 전 예약을 하나의 영속 기록으로 합산하세요. 소진 시 한도를 자동 확대·초기화하지 말고 다른 작업을 계속합니다. 이 한도는 Goal 도구의 token_budget와 별개입니다. 호스티드 키가 없으면 허용된 실제 로컬 추론 API가 가능한지 확인하고, 그동안 runner와 결정적 테스트를 완성합니다. 실제 모델 실행이 없으면 해당 기준은 미완료입니다. 실제 모델+실제 CSE에서 오래된 관측·권한 거부·미회복 사례 중 하나 이상도 처리하고, 최종 보고가 미해결 상태와 일치하는지 검증하세요.
- 실제 Codex 호스트 설치 확인이 막혀도 플러그인 패키징·MCP·서비스 검증과 다른 작업을 계속합니다. MCP 테스트만으로 Codex 설치 검증을 통과시키지 마세요.
- MEC와 handover는 필요성과 환경을 확인해 채택 여부를 정합니다. FL·위치 기능은 합리적 필요가 생기기 전에는 보류합니다. 로컬 Docker나 mock을 실제 MEC 증거로 표시하지 마세요.
- 가상 장치 자동 조치는 합의된 데모 범위에서 진행합니다. 실제 장비는 관측·진단 기본값을 유지하고, AI가 자기 권한을 늘릴 수 없게 하세요.
- 권한 정책·자동 승인 심사·계정 접근·예산 제한을 우회하지 마세요. 프로젝트 테스트 환경의 최소 권한 ACP·역할 자격증명·TLS 구성은 허용됩니다. 호스트·계정·조직·승인 보호 정책이나 전역 신뢰 저장소 변경, 새로운 구매, 유료 인프라 생성, 무관한 자료 삭제, 실제 장비 제어, 외부 메시지 발송이나 별도 서비스 제출은 이번 위임에 포함되지 않습니다. 이런 작업 대신 허용된 대안을 진행하고 필요한 인계 사항을 남기세요.
- 같은 외부 오류를 무한 재시도하지 말고 원인·시도·대안·재개 조건을 기록합니다. 유의미한 허용 작업이 남아 있으면 계속합니다. 모든 경로가 실제로 소진되면 도구에 정해진 blocked 처리 규칙을 따르고, 미완료를 완료로 보고하지 않습니다.

고급 SDT/semantic·MEC·handover 등 조건부 확장은 검토된 보류가 가능하지만, 실제 CSE·Codex 호스트 검증·실제 LLM 실행 같은 필수 기준은 막혔다고 면제하지 않습니다. 확장별 채택/보류·이유·게이트·환경·증거·검토와 이력을 기록하세요. 모든 확장은 완료 전에 검토된 채택/보류 결정을 가져야 합니다. 미결정·조사 중인 항목이나 채택한 미완료 확장이 남으면 전체 완료가 아니며, 보류해도 이전 실패 기록은 보존합니다. fixture, API 연결 확인, 실제 모델 전체 실행 결과를 구분하세요. 근거 없는 점수·85점 공식 총점·수상 확률을 만들지 마세요.

docs/execution-state.json에 현재 단계/기준, 증거 경로, 검토 상태, 담당자·소유 파일·기준 revision·다음 행동을 포함한 위임 작업, 시도·대안·해제 조건을 포함한 막힘, 계획 변경 이유와 산출물 위치/해시/공개 상태를 남기고, docs/review/review-ledger.json에 검토 의견을 관리하세요. 의미 있는 단위로 검증·커밋·GitHub 반영을 진행하며 문맥이 압축되어도 마지막 체크포인트에서 이어가세요. 짧은 진행 설명은 하되, 단순히 계속할지 묻기 위해 작업을 끝내지 마세요.

완료는 필수 기준의 실행 증거와 독립 검토, 검토된 조건부 확장 처리, 저장소 반영으로 판단합니다. Hackster/영상 플랫폼 게시·Discord 제출은 별도 허가가 없는 한 실행하지 않고 바로 게시 가능한 자료와 인계 목록을 준비합니다. 이 준비와 실제 대회 제출을 구분하세요. 필수 외부 검증이 남아 있으면 전체 목표는 완료가 아닙니다.

이제 0단계의 시나리오·계약·실행 환경·초기 코드 구조부터 실제 작업을 시작하고, 각 단계의 검증 결과를 바탕으로 다음 단계까지 계속 진행해주세요.
```

단계별 성공 증거와 외부 의존성 처리는 [구현 계획](implementation-plan.md)에 정의되어 있습니다. Goal 모드도 권한과 실행 제한 안에서 동작하므로 무중단을 보장하는 프롬프트는 아닙니다. [공식 Goals 안내](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex), [자동 승인 심사 안내](https://learn.chatgpt.com/docs/sandboxing/auto-review).
